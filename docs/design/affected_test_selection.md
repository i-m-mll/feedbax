# Affected test selection

Run `uv run --no-sync python scripts/affected_gate.py --base <commit>` while editing. The command selects Python and Studio tests independently and runs browser, build, and generated-contract checks when the changed inputs require them. `--plan` prints the gate decisions without executing them. A broadened Python or Studio gate still runs against the working tree. A dirty checkout does not prevent those checks; the report keeps clean-wheel conformance pending until a committed candidate is ready. Run `uv run --no-sync python scripts/affected_gate.py --reference` on a clean committed candidate for clean-wheel conformance, generated-contract drift, the complete Python core suite, Studio unit tests, Chromium scenarios, and build.

Pants 2.33.0 provides the Python reverse-import graph from repository BUILD targets. The selector validates first-party imports from Python syntax and refuses an inference error rather than silently reporting success. If `pants` is absent from `PATH`, a checksum-pinned scie-pants v0.13.2 launcher is installed in the user cache. [Pants installation](https://www.pantsbuild.org/stable/docs/getting-started/installing-pants) describes the launcher; uv remains the Python dependency and execution authority. Installed Vitest supplies the Studio related-test graph, and Bun runs Studio checks.

The plan selects edited Python tests and transitive dependents of ordinary Python source, and edited Studio tests and related Studio source tests. Shared graph, registry, runtime, schema, and generated-contract changes broaden the relevant gates. Deleted paths, external plugin sources, and unproved inputs broaden the possible domains with a reason. Literal test-fixture references are derived from Python `Path(__file__)` expressions and Studio `new URL(..., import.meta.url)` expressions; an unrecognized fixture has broader coverage. The shared acausal report fixture selects its Python compile-report test and Studio acausal test.

The selected Python files run through the existing full-suite wrapper, including its lock, native-thread budget, JAX cache, and temporary cleanup. Every core test case in each selected file runs. The plan separately reports optional MJX and PPO markers found in selected files. `--include-capabilities` runs those optional cases when the required environment is available; otherwise the report says they remain pending. The reference gate covers the core profile, while optional capability coverage is an explicit separate obligation.

Use `uv run --no-sync python -m scripts.affected_tests --replay <commit> --source-only` to replay a historical production-only diff against the current graph. Affected test selection is a development gate; the complete reference remains the integration acceptance gate. The registry-owned projection identifies component IDs and their source paths. For a component source change, the plan reports literal graph and fixture witnesses but runs broad Python, Studio, browser, build, and generated-contract gates until indirect consumers and failure recall justify narrower coverage.
