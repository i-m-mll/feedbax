## 2. Concerns

### Policy violations (repo CLAUDE.md — durable schema requires versioned migration)

- **`feedbax/persistence/database.py` — no alembic migration for schema changes.** New `nullable=False` / `index=True` constraints were added to `ModelRecord` (`hash_version`, `created_at`, `is_path_defunct`, `postprocessed`, `has_replicate_info`, `expt_name`, `pert__type`, `pert__std`). No `alembic/` directory exists anywhere in the repo. The only schema-evolution mechanism, `update_table_schema()`, only adds missing columns via `Operations.add_column` — it does not retroactively add indices or tighten nullability on existing on-disk SQLite tables (`metadata.create_all(checkfirst=True)` is a no-op once a table exists). Any pre-existing `models.db` created under `develop` silently lacks the new index/constraint, with no migration path and no test exercising open-old-db behavior.

- **`feedbax/contracts/migrations.py` (~lines 977, 994) — silent substitution reintroduced one level down.** `migrate_studio_workspace_spec`, called from durable-load paths (`feedbax/studio/schema.py:188`, `feedbax/integrations/provider.py:2160`), unconditionally passes `assume_current=True` when recursing into nested `scenarios`/`stages` sub-payloads. This is the exact silent-substitution pattern the top-level versionless-payload fix (child 3) eliminated, reappearing in nested payloads. Confirmed by design: a new test, `test_studio_workspace_explicitly_accepts_current_versionless_scenario_specs`, asserts `"schema_version" not in objective_spec` is silently accepted. No test distinguishes "freshly authored, never versioned" from "loaded from an old durable file whose nested payload predates versioning" — exactly the ambiguity the no-silent-substitution principle exists to prevent.
