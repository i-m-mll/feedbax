# Python duplication census and attention list

Mandible-Issue: 34a99c3

Measured at `08cd1657` on the tracked tree. Nothing here is a proposal to merge,
delete, or refactor. A low distance is a reason to open two files side by side;
it is never on its own a reason to unify them.

## Instruments

| Instrument | What it measures | Blind to |
| --- | --- | --- |
| `scc` | lines, by language and directory | everything semantic |
| Alpha-normalized NCD scan | whole declarations that carry the same structural information after locally bound names are renamed and literals erased | anything smaller than a declaration; anything spread across declarations |
| `jscpd` | contiguous token runs that are exactly equal after light normalization | anything renamed on paste; anything reordered |

The NCD scanner is Mandible's `scripts/ncd-scan.mjs`. Its Python extractor was
added under Mandible issue `5234372`: units are parsed by Python's own `ast`,
serialized as a preorder token stream, with parameters, locals, comprehension
and `except` bindings alpha-renamed to `$0`, `$1`, …, while free identifiers —
call targets, import aliases, attribute names, keyword-argument names, class
field and method names — are kept verbatim, because those are the external
contract a unit participates in rather than a locally arbitrary choice. String
and numeric payloads are erased. Pairs are prefiltered by exact Jaccard over
token 5-shingles and then scored by

    NCD(x, y) = (C(xy) - min(C(x), C(y))) / max(C(x), C(y))

with a fixed `deflateRaw`. Lower is more similar; 0.0 would mean one unit adds
no information the other does not already carry.

### Reproducing

```
git -C <feedbax> archive --format=tar HEAD | tar -x -C <workdir>
scc --no-gitignore --no-ignore <workdir>

node <mandible>/scripts/ncd-scan.mjs \
  --root <feedbax> --config <this config> \
  --out feedbax-python --top 100000 --include-dropped

( cd <workdir> && jscpd . --format python \
    --min-tokens 50 --min-lines 5 --max-lines 100000 --max-size 10mb \
    --reporters json,console --output <out> )
```

`jscpd`'s `--max-lines` default is 1000 and its `--max-size` default is 100 kB.
Both silently drop files rather than reporting them, and Feedbax has 15 Python
files above 3,000 lines. Running `jscpd` at its defaults on this repository
measures a different population than the one you asked about.

## What was excluded, and on what basis

The file set is `git ls-files`, never a filesystem walk. That single decision
removes every trap by construction rather than by an exclusion list that has to
stay current, and it is checkable: the scan reported **742 files**, and
`git ls-files '*.py' | wc -l` is **742**. The traps that would otherwise have
dominated the output, and their status:

| Trap | Tracked files reaching the scan | Why |
| --- | ---: | --- |
| Per-run provenance snapshots in a sibling repo (841 run directories, each a verbatim copy of the Feedbax source that produced it) | 0 | Not in this repository at all, and not tracked where they live. Had a filesystem walk reached them they would have produced perfect self-similarity at every rank. |
| `_artifacts/` and any `.repo-snapshots/` tree | 0 | Untracked. Also pattern-excluded as a belt. |
| `.venv/` | 0 | Untracked. Thousands of third-party files. |
| `worktrees/` — eleven full checkouts of this same repository | 0 | Untracked. Every file would have matched itself exactly. |
| `node_modules/`, `__pycache__/`, build output, caches | 0 | Untracked. |

Confirmed by `git ls-files | grep -c` returning 0 for each of `^worktrees/`,
`\.venv/`, `_artifacts/`, and `repo-snapshot`.

**Generated code was classified, not excluded.** Structural similarity between
generated files is correct output, and hiding it would hide the fact that it is
correct. Detection is structural — the marker the generator writes into the
first 4 KiB of the file — not a path list. Exactly one Python file is generated:

- `feedbax/components/equinox.py`, 1,636 lines, from `scripts/generate_eqx_components.py`.
  Its 94 internal pairs are reported in the scan's dropped section rather than
  the ranked list. `jscpd`, which has no such notion, ranks it as the single
  largest source-to-source duplication in the repository at 725 duplicated
  lines, and additionally reports 96 lines shared with its own generator — which
  is the generator's templates, not duplication.

`scripts/generate_studio_contracts.py` emits TypeScript into
`web/src/generated/`, outside this scan.

The narrow generated-header patterns matter. A bare `generated by` pattern
matches ordinary prose — `feedbax/mechanics/muscle.py` contains "the tensile
force generated by the muscle" — and a false positive silently demotes a real
finding into the dropped section, which is the failure mode that is hardest to
notice.

**One file failed to parse:** `docs/notebook_preamble.py` is a notebook preamble
containing IPython magics and is not valid Python. It is reported as an
extraction error rather than dropped silently.

**Tests, fixtures, and the `external/` conformance fixture package** are tagged
and their pairs are moved out of the primary ranked list into an auditable
dropped section. They are analyzed in [Cluster E](#cluster-e--the-test-suite).

### Where the two tools agree

Of the NCD scan's top 50 pairs, **39 (78 %)** are also a `jscpd` clone file pair,
and **15 (30 %)** have a single `jscpd` clone that covers both whole units. The
first figure says the tools are looking at the same regions; the gap to the
second says they are describing them differently — `jscpd` usually reports a
fragment of a declaration, not the declaration.

### Where they disagree, and why

**NCD finds copies that were renamed on paste; `jscpd` cannot.** The clearest
case is `_sha256_file`. Three copies exist. Two are byte-identical and `jscpd`
reports them. The third, in `training/checkpoint_custody.py:6795`, differs only
in that `h` was renamed to `digest` and `handle` to `stream`. It scores NCD
0.062 against both others — indistinguishable from the byte-identical pair — and
`jscpd` does not report it at all. This is the entire reason for
alpha-normalization and it earned its keep on the first run.

**`jscpd` finds duplication below and across declaration boundaries; NCD cannot.**
NCD's unit is a whole declaration, so a repeated 30-line block inside two
otherwise different functions is invisible to it. The cross-file source pairs
`jscpd` reports that no NCD pair covers are led by
`mechanics/muscles/relu_muscle.py ~ thelen_muscle.py` (32 lines),
`component_registry/acausal_adapters.py ~ contracts/graphs/acausal_compiler.py`
(21), `control/continuous.py ~ control/pid.py` (20), and
`mechanics/templates/arm_6muscle.py ~ pointmass_muscles.py` (14). These are real
and are not in the ranked list below.

**`jscpd` has no notion of generated code**, so its largest single finding is an
artifact of its own blindness.

Use both. Neither is a superset.

### Cluster C — the rotational/translational duality in `acausal/`

`acausal/rotational.py` (293 lines) and `acausal/translational.py` (314 lines)
are the same eight element types written twice. `Inertia`/`Mass`,
`TorsionalSpring`/`LinearSpring`, `RotationalDamper`/`LinearDamper`,
`TorqueSource`/`ForceSource`, `RotationalGround`/`Ground`,
`AngleSensor`/`PositionSensor`, `AngularVelocitySensor`/`VelocitySensor`,
`TorqueSensor`/`ForceSensor`. Cross-file NCD runs 0.065–0.083 for the classes and
0.070–0.097 for their `__init__`s; the corresponding within-file sensor triples
score 0.046. This is 133 of the 747 primary pairs — 18 % of the whole ranked
list from 1.4 % of the library — and `jscpd` independently reports 93 + 75 + 39
duplicated lines across the two files.

The entire difference between the two modules is three values:
`Domain.ROTATIONAL` vs `Domain.TRANSLATIONAL`, across-vars
`("angle", "angular_vel")` vs `("pos", "vel")`, and through-var `"torque"` vs
`"force"`. The equation bodies, port construction, and parameter registration
are identical.

**Shared concept:** a mechanical domain descriptor. One
`Domain(across_vars, through_var)` value and one set of element constructors
parameterized by it would replace both files.

**Worth acting on:** probably, but this is the cluster where I would most want
the owner's judgement rather than mine. Acausal modelling libraries duplicate
this duality by convention — Modelica's `Mechanics.Rotational` and
`Mechanics.Translational` are separate packages for exactly these elements — and
the duplication buys domain-correct names in tracebacks and docstrings. In
Modelica the duplication is forced by the language; in Python it is not. The
honest summary is that the cost is ~290 lines and the benefit is naming.

## Limits

- A low NCD says two declarations carry overlapping structure. It says nothing
  about transaction boundaries, ordering guarantees, error semantics, or
  authority boundaries — which are exactly what decide whether unifying is
  sound, and are invisible to a compressor.
- The unit is a whole declaration. Duplication inside a declaration, or spread
  across several, is invisible to this scan; `jscpd` covers part of that gap and
  its findings are listed above.
- Literals are erased, so two functions that differ only in a constant score as
  identical. That is the intended behaviour for finding copies and the wrong
  behaviour for judging them.
- `deflate`'s window is 32 KiB. No unit in this scan exceeded it, so no pair here
  is window-limited, but the flag exists in the output.
- The bound-name set is per-unit and keyed by string, so a local variable that
  shares a method's name in the same class is left free. This can only make two
